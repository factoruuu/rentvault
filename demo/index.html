RentVault

Rental security deposits, held by code — not by trust. A renter's deposit is locked in an Ootle component and can only leave by rules both sides agreed to up front: mutual release, a claim that survives a dispute window, or an automatic refund if the owner never claims.

Simulation Template + engine tests are real
1Lock The renter deposits the agreed amount into the RentVault component. Neither side can touch it while the rental runs.
2Return or claim Item back in good shape? Both sides confirm and the deposit refunds in full. Damaged? The owner files a claim for up to the deposit.
3Settle A claim only pays out after a dispute window the renter can contest. If the owner never claims, anyone can trigger a full automatic refund. Funds can never get stuck.

What is real: the Rust template in template/ compiles to WASM and is exercised by engine tests (tari_template_test_tooling) that run the same Ootle engine as the network — every transition and rejection on this page mirrors a tested code path. What is simulated: this page. It runs the same state machine in JavaScript so you can click through it without a wallet; it is not connected to a network.

The dispute rule, honestly: if the renter disputes a claim inside the window, the claim is voided and the deposit refunds in full. RentVault is a custody layer, not a court — a contested deduction moves off-chain, where the claim and dispute are both on the public record as evidence. What the chain guarantees is that an owner can never keep a deposit silently, by default, or after the deadline.
